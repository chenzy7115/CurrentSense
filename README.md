# ESP32 有感 FOC —— 电流（力矩）闭环移植分析

本工程由 DengFOC Lesson8 电流力矩闭环例程移植到 **PlatformIO + Arduino-ESP32 3.x**，使用 AS5600 获取转子电角度，使用低侧采样电阻与运放采集 A/B 相电流，经 Clarke/Park 变换得到 q 轴电流 `Iq`，再由电流环调节三相电压。

本文同时记录与参考工程的逐项比较、运行可行性、已发现问题和优化建议。分析日期：**2026-11-25**。本次只修改文档，没有修改控制代码。

## 6. 算法正确性分析

### 6.1 电流采样与 Clarke 变换

实现位于 `M/lib/DengFOC/src/InlineCurrent.cpp:120-123` 和 `M/lib/DengFOC/src/DengFOC.cpp:200-209`。

```text
Ia = (ADC_A - offset_A) × 2 A/V
Ib = (ADC_B - offset_B) × 2 A/V
Iα = Ia
Iβ = (Ia + 2Ib) / √3
Iq = Iβ cos(θe) - Iα sin(θe)
```

在两相采样方向、增益和硬件极性正确的前提下，该变换与参考版一致，也与输出侧逆 Clarke 变换相对应。

需要注意：`Sensor_DIR` 只改变电角度和速度方向，**不会自动修正采样电流的正负号**。若运放输出反相，应修正采样极性或电流换算增益，不能仅靠 `Sensor_DIR` 解决。

### 6.2 电压输出

实现位于 `M/lib/DengFOC/src/DengFOC.cpp:122-137`。

```text
Uα = -Uq sin(θe)
Uβ =  Uq cos(θe)
Ua = Uα + Vbus/2
Ub = (√3 Uβ - Uα)/2 + Vbus/2
Uc = (-Uα - √3 Uβ)/2 + Vbus/2
```

`Uq` 被限制在 `±Vbus/2`，相电压被限制在 `0~Vbus`。该实现属于中心偏置的三相逆变器输出，不是单独的过调制 SVPWM 算法。对于本章圆形电压轨迹，逻辑可用；若以后需要弱磁或更高电压利用率，再单独设计过调制，不能只提高限幅。

### 6.3 电角度与对齐

实现位于 `M/lib/DengFOC/src/DengFOC.cpp:168-185`。

```text
θe = normalize(DIR × PP × θmech - zero_electric_angle)
```

上电时输出固定 3 V 电压矢量，等待 1 s，记录零电角度后松劲。该流程与参考版一致，但存在两个限制：

1. 若电机带较大负载，1 s 内可能无法到达对齐位置，记录的零角度不可靠。
2. 若编码器读数失败或电机极对数错误，程序仍会把错误结果当作有效零角度。

### 6.4 PID 与滤波

- PID 使用 `micros()` 计算实际周期，梯形积分，积分项和总输出分别限幅，最后执行输出斜率限制，见 `M/lib/DengFOC/src/pid.cpp:29-63`。
- 电流环输出量是电压，但构造限幅写成 `12.6`，即 ±12.6 V；随后 `setTorque()` 又限制到 ±6.3 V。因此最终电压受 `Vbus/2` 限制，±12.6 不是电流保护值。
- `ramp=100000` 在几毫秒周期下几乎不产生实际限制，不应把它当作有效的启动缓启动。
- 电流低通实际时间常数为 `0.05 s=50 ms`，不是源码注释中的 5 ms，见 `M/lib/DengFOC/src/DengFOC.cpp:23`。
- 50 ms 滤波会给电流反馈带来明显相位滞后。它是否导致振荡取决于实际环路周期、电机电阻/电感、惯量和负载，不能脱离硬件给出固定 PID 值。

## 7. 问题清单与风险分级

### P0：带载前必须处理

#### P0-1 上电即使能，安全状态不明确

`M/src/main.cpp:19-22` 先把 GPIO12 拉高，再初始化 PWM、编码器和 ADC。此时功率级已经允许输出，而 PWM 引脚可能仍处于默认状态。若驱动器在该窗口出现非预期占空比，可能产生突加电流、异相驱动或开关管直通风险。

**建议**：先保持 EN 低；将三路 PWM 明确置为已知安全状态；完成 PWM、I2C、ADC 初始化和自检；确认传感器有效后再使能。GPIO12 还是 ESP32 的上电 strap 引脚，还应核对开发板拨码/外部上下拉与目标驱动板的兼容性。

#### P0-2 默认方向被改变且文档不一致

`M/src/main.cpp:10` 为 `1`，`R/*.ino:10` 为 `-1`。原 README 曾把移植版默认值写成 `-1`，与代码不符；本文已按源码更正。

**建议**：不要凭经验直接选定。先确认极对数，再在低母线电压、限流、电机可自由转动、有人看护的条件下测试方向和对齐。每次修改方向都必须重新上电对齐。

#### P0-3 没有目标电流限制和过流停机

`M/lib/DengFOC/src/DengFOC.cpp:235-265` 对串口数字没有范围检查，`M/lib/DengFOC/src/DengFOC.cpp:296-298` 也不限制目标 `Iq`。`setTorque()` 只限制电压，不能替代电流保护。

**建议**：

- 接收指令时检查完整解析、`isfinite()` 和 `|Iq| <= Iq_limit`。
- 用独立于控制算法的过流比较器/驱动芯片保护作为最终硬件保护。
- 软件检测相电流、直流母线或驱动器故障，超限后立即关闭 PWM/使能并锁存故障。
- 上电默认目标为 0，不接收串口也必须保持无输出。

#### P0-4 I2C 错误被当作正常角度

`M/lib/DengFOC/src/AS5600.cpp:20-27` 没有检查 `endTransmission()`、`requestFrom()` 和读取字节数。AS5600 断线、地址错误或总线受扰时，`read()` 可能返回 `-1`，被转成 `0xFF`，从而拼出 4095 附近的错误角度。

**建议**：检查每一步返回值，缓存上一拍有效角度，统计连续错误；短时错误可拒绝更新，连续错误必须停机。初始化时增加 AS5600 状态/磁场强度检查，不要仅用固定 `delay(500)` 代替就绪检测。

#### P0-5 ADC 量程和采样有效性未校验

`M/lib/DengFOC/src/InlineCurrent.cpp:12-16` 使用理想 `3.3/4095` 换算，`configureADCInline()` 只设置 `INPUT`，没有显式配置 12 bit 分辨率和 ADC1 衰减，也没有检查饱和读数。

**建议**：显式设置 `analogReadResolution(12)`、`analogSetPinAttenuation(pin, ADC_11db)`（按实际硬件信号范围选择），校准零漂和增益，并在代码中标记 ADC 饱和。若运放输出接近 0 V 或 3.3 V，应按异常处理，不能继续闭环。

### P1：影响闭环质量与稳定性

#### P1-1 电流遥测重复推进滤波器

`M/src/main.cpp:36` 先通过 `DFOC_M0_setTorque()` 调用一次 `DFOC_M0_Current()`，`M/src/main.cpp:42` 打印时又调用一次。`DFOC_M0_Current()` 内部会更新滤波器时间戳和历史值，因此每 31 个循环会出现一次“同一原始输入被再滤波一次”的扰动。

**建议**：每个控制周期只采样、只计算、只滤波一次。把 `Iq` 保存为本拍结果，控制与遥测共同使用；增加纯读取接口 `getFilteredCurrent()`。

#### P1-2 无固定周期、无 PWM 同步采样

主循环周期由 I2C、ADC、串口和代码执行时间共同决定。30 kHz PWM 与 ADC 读取没有硬件触发关系，A/B 两相还是顺序采样，可能处于不同开关状态。

**建议**：

1. 先测量各阶段耗时和周期抖动，记录最小/平均/最大 Ts。
2. 用 ESP32 定时器或 FreeRTOS 固定周期任务组织控制环，超时丢帧而不是追赶执行。
3. 高级阶段使用 LEDC 定时器事件或 ADC 数字控制器，在 PWM 特定点触发 A/B 两路采样，并校正采样偏斜。
4. 串口、日志和调参放到低优先级任务，通过队列/快照通信。

#### P1-3 50 ms 电流滤波可能过大

`M/lib/DengFOC/src/DengFOC.cpp:23` 的 `Tf=0.05` 直接用于闭环反馈。较大的滤波会降低噪声，但会增加相位滞后。

**建议**：先用电流带宽和实际 Ts 估算可用滤波范围，再从小时间常数开始测试；控制通道与显示通道可使用不同滤波器，不要把显示滤波直接串入反馈。修改后必须重新做阶跃和扫频测试。

#### P1-4 PID 只有积分限幅，没有条件积分/反饱和

`M/lib/DengFOC/src/pid.cpp:39-48` 在输出饱和后仍会继续积累积分。虽然积分自身限制在 ±limit，但反向误差出现时可能需要较长时间退出饱和。

**建议**：当未饱和输出与实测输出符号不一致时冻结或回算积分；在 `Target=0`、模式切换、对齐完成和故障恢复时显式复位 PID 状态。

#### P1-5 对齐过程过于简化

`M/lib/DengFOC/src/DengFOC.cpp:176-185` 固定输出 3 V 并固定等待 1 s，没有确认转子是否稳定，也没有限制对齐阶段电流。

**建议**：逐步升压，监测角度变化率和电流；超过对齐时间或电流仍未稳定就判定失败。记录对齐质量，失败时保持输出关闭。

### P2：协议、可维护性与工程化

#### P2-1 串口输入非法值会直接变成 0

`String::toDouble()` 解析失败返回 0，且没有缓冲区长度上限。`M/lib/DengFOC/src/DengFOC.h:51` 声称“解析失败不会改动原目标值”，与实现不一致。

**建议**：使用定长字符缓冲区和 `strtod()`，检查结束指针、`errno`、`isfinite()` 与目标范围；失败时保留旧值并返回错误码。支持 `\r\n`、单字符超时和缓冲区溢出恢复。

#### P2-2 回显与测量值共用同一纯数字通道

`M/lib/DengFOC/src/DengFOC.cpp:258` 打印目标值，`M/src/main.cpp:42` 打印测量值，两者都没有类型标识，串口绘图器会同时看到目标回显和电流曲线。

**建议**：改成带前缀的帧，例如：

```text
SET,1.500
IQ,0.012345
ERR,OK
```

同时加入序列号、时间戳、CRC 或 checksum；目标回显与实时测量分开处理。

#### P2-3 每拍重复设置 PID 参数

`M/src/main.cpp:35` 每个循环都调用 `DFOC_M0_SET_CURRENT_PID()`。数值不变，但会重复赋值，也增加调参时意外改变环路的入口。

**建议**：只在初始化或收到调参指令时设置；正常控制循环只执行采样和运算。

#### P2-4 未使用的速度/角度接口仍有固有问题

`M/lib/DengFOC/src/DengFOC.cpp:283-285` 的 `DFOC_M0_setVelocity(float Target)` 忽略入参并使用串口目标；速度误差还乘以 `180/PI`。本章主循环没有调用它，因而不影响当前力矩闭环，但保留在公共库中容易误用。

**建议**：要么修正接口和单位，要么从本章最小工程中移除；`DFOC_M0_Angle()` 的多圈计数也只是软件累计，不能替代上电绝对位置。

#### P2-5 工具链和依赖未锁定

`M/platformio.ini:11-17` 只指定 `platform = espressif32`，没有固定版本。

**建议**：记录并固定已验证的 Platform、Arduino core 和工具链版本；保留构建产物大小与告警基线，升级依赖后重新回归。

## 8. 优化实施建议

以下为建议优先级，不表示本次已经实现。

### 第一阶段：达到可安全上电测试

1. 将启动流程改为“EN 低 → PWM 安全占空比 → PWM/I2C/ADC 初始化 → 自检 → 校准 → 限流对齐 → EN 高 → 目标为 0”。
2. 增加 `init_ok`、`sensor_ok`、`fault_latched` 状态；任何初始化失败都不进入闭环。
3. 加入配置项 `Iq_limit`，在指令入口和力矩入口双重限幅。
4. 增加软件过流关断，同时保留驱动器硬件过流保护。
5. 检查 I2C 返回值；AS5600 连续失败时锁存故障。
6. 确认 GPIO12 的 strap 行为和驱动板 EN 极性。
7. 用实际电机确定 `Motor_PP` 与 `Sensor_DIR`，记录测试条件。

### 第二阶段：提高电流环性能

1. 每个控制周期只更新一次电流采样和滤波状态，遥测读取缓存值。
2. 将控制循环改为固定 Ts，并统计周期抖动。
3. 从低于 50 ms 的反馈时间常数开始标定，而不是直接复制参考参数。
4. 为 PID 增加条件积分和复位接口。
5. 做 PWM 同步采样或至少量化 A/B 采样偏斜与 PWM 相位偏差。
6. 对齐阶段加入限流和稳定性判据。

### 第三阶段：完善协议与可维护性

1. 将纯数字串口改为带类型的帧协议，并限制输入长度。
2. 修正头文件“解析失败保留目标”的承诺，或修改实现使其成立。
3. 删除/隔离非力矩闭环接口，避免单位错误扩散。
4. 锁定工具链版本，增加静态检查、主机端算法单元测试和上板回归清单。

## 9. 推荐的上板验证流程

> 电机第一次上电存在突然运动和绕组发热风险。使用低电压、小电流限值、可空载转动电机，并准备硬件急停/断电措施。

### 9.1 静态检查

- 确认电机极对数，不能仅凭电机外径猜测。
- 确认母线电压、驱动器耐压、采样电阻功耗和运放输出范围。
- 确认 A/B/C 相线、编码器 SDA/SCL、采样通道和 EN 极性。
- 万用表检查无短路、无虚接，AS5600 磁体距离和方向正确。
- 示波器确认三路 PWM 频率为 30 kHz，且上电过程中没有危险占空比。

### 9.2 仅传感器测试

先不使能功率级，读取并打印：

- AS5600 原始计数、角度、I2C 错误计数。
- A/B ADC 原始计数、零漂电压、换算电流。
- 控制周期 `Ts`。

手动转动电机，确认角度连续变化；跨 0/2π 时累计圈数方向正确。静态时两相电流应接近 0，且无 ADC 饱和。

### 9.3 低能量对齐测试

- 使用低母线电压和很小的对齐电流限制。
- 观察对齐期间相电流是否越限、角度是否最终稳定。
- 若电机不动、剧烈抖动或持续升流，立即断电，检查 PP、方向、采样极性和相序。
- 多次上电检查 `zero_electric_angle` 是否具有可重复性。

### 9.4 电流环阶跃测试

在安全限流内依次发送 `0 → +0.2 A → 0 → -0.2 A → 0`，记录：

| 指标 | 需要观察的内容 |
| --- | --- |
| 上升时间 | 实测 Iq 达到目标一定比例所需时间 |
| 超调 | 是否超过设定电流或硬件安全阈值 |
| 稳态误差 | 长时间后 Iq 与目标偏差 |
| 振荡 | 是否出现持续衰减振荡或等幅振荡 |
| 方向一致性 | 正目标是否产生预期方向的力矩 |
| 周期抖动 | 串口输出时 Ts 是否明显变化 |
| 温升 | 驱动器、采样电阻、电机绕组温升 |

先用 `I=0` 标定比例环，再逐步引入小积分。不要一开始就使用较大的 `I=200`。每次调整只改一个参数，并保留测试记录。

### 9.5 回归条件

至少验证以下情况：

- 上电、复位、重新烧录。
- 编码器断线、ADC 饱和、驱动器故障。
- 非法串口字符、超长帧、无换行、连续多帧。
- 串口监视器开关与大量日志输出。
- 不同母线电压和电机负载。

## 10. 使用说明

### 10.1 参数位置

在 [src/main.cpp](src/main.cpp) 修改：

- `Motor_PP`：电机极对数。
- `Sensor_DIR`：编码器方向，当前源码值为 `1`。
- `DFOC_Vbus(12.6)`：实际供电电压。
- `DFOC_M0_SET_CURRENT_PID(5, 200, 0, 100000)`：电流环 P/I/D/输出斜率。

上述参数是参考版起点，不是经过本机硬件验证的最终参数。修改源码参数后必须重新编译并重新上电对齐。

### 10.2 编译、烧录与监视

```powershell
# 编译
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run

# 烧录，可追加 --port COMx 指定串口
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -t upload

# 115200 串口监视
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device monitor
```

若 `pio` 已在 PATH 中，也可以直接使用 `pio run`、`pio run -t upload`、`pio device monitor`。

### 10.3 当前串口协议

波特率 115200，一帧以 `\n` 结束：

| 方向 | 示例 | 当前行为 |
| --- | --- | --- |
| 下发 | `1.5\n` | 设置目标 Iq=1.5 A；**当前没有安全限幅** |
| 目标回显 | `1.500000` | 目标值，无类型标识 |
| 电流上报 | `0.012345` | 每约 31 个控制循环一次，无类型标识 |

当前实现不支持显式的“启动/停止/故障确认”命令。完成 P0 优化前，不建议远程或无人值守发送非零目标。

## 11. 常见故障排查

| 现象 | 优先检查 |
| --- | --- |
| 上电立即猛动或撞车 | EN 时序、PWM 初始占空比、GPIO12 strap、采样极性 |
| 对齐时电机不动 | 母线电压、EN、PWM、相线、编码器、电机负载 |
| 对齐时持续升流 | 极对数错误、方向错误、采样反相、对齐电压过大 |
| 正目标产生反向力矩 | `Sensor_DIR`、电流采样极性、电机相序 |
| Iq 数值很大但电机无力 | ADC 饱和、零漂错误、采样方向、增益/分流电阻参数 |
| Iq 在 0 附近但方向随机跳变 | AS5600 断线或 I2C 错误、磁体偏移/过弱 |
| 电流环持续振荡 | 50 ms 反馈滤波、周期抖动、PID 增益、采样相位 |
| 开串口后控制变差 | 串口阻塞、周期抖动、滤波时间戳异常 |
| 发送字母后目标变 0 | 已知 `toDouble()` 无校验问题 |
| 修改方向后仍不正常 | 修改后是否重新上电对齐、采样极性是否也需修正 |
